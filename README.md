# 南華大學法規全文庫 — 使用說明

**每學期更新只要一行：**

```bash
python 更新.py --zips ./法規
```

它會依序備份上一版、重新解析、與上一版比對、稽核、表格檢查、產生網頁，
最後給你一份「這次到底變了什麼」的 `更新報告.md`。加 `--skip-tables` 可略過
比較耗時的表格檢查。

比對才是這支腳本存在的理由。重新解析誰都會做，難的是回答「這學期哪幾部法規動了」——
沒有這個，你沒辦法跟各單位交代，也沒辦法判斷網頁該不該重新上傳。它會分成五類：
新增、已移除、修正、**內容變動但通過日期未變**、更名。第四類最值得看，
那是唯一會讓人拿到新內容卻以為是舊版的情況。

---

以下是各支腳本單獨執行的方式。全部本機執行，不需要連外。

```bash
pip install python-docx pdfplumber odfpy
# 舊版 .doc 需要 LibreOffice：brew install --cask libreoffice / apt install libreoffice

# 1. 先盤點，不寫資料庫 —— 看清楚各單位到底交了什麼
python nhu_regs.py inventory --zips ./法規委員會 --out 盤點.csv

# 2. 解壓、解析、入庫（預設只處理「法規」，不碰 SOP）
python nhu_regs.py ingest --zips ./法規委員會 --work ./work --db regs.db
#    之後要把 SOP 一起收進來：--kinds 法規,SOP

# 3. 產生單檔查詢網頁（資料直接內嵌，雙擊即開，可放共用磁碟或內網）
python nhu_regs.py build-site --db regs.db --template template.html --out 法規查詢.html

# 額外：命令列檢索
python nhu_regs.py search 休學規定 --db regs.db
```

`--zips` 指向從雲端下載下來的資料夾。單位名稱、法規／SOP 分類、版本時間戳
都是從 zip 檔名解析的（`人事室單位法規-20260821T081404Z-1-001.zip`），
所以**不要改壓縮檔的檔名**。

同一個單位若有多個壓縮檔（補件、重交），程式只採用**時間戳最新**的那一份，
並在畫面上告訴你它跳過了哪個。舊檔留在雲端不會造成重複資料，
但看到那行訊息時還是回頭確認一下新版本是不是你要的。

## 兩份紀錄，分開看

| 檔案 | 誰寫的 | 記什麼 |
|---|---|---|
| `變更紀錄.md` | 人工，每次改程式後補 | 程式與網頁改了什麼、為什麼改、影響什麼。標 ⚠ 者會改變查詢結果 |
| `建置紀錄.md` / `.csv` | `更新.py` 自動追加 | 每次建置的法規數、變更數、品質數字，一次一筆流水帳 |

分開是刻意的。混在一起的話，找「上學期哪幾部法規動了」會被程式改版的紀錄淹沒，
找「為什麼查詢結果跟半年前不一樣」又會被一堆數字埋掉。

查詢頁頁尾顯示介面版本（目前 v1.9）。**同仁回報問題時請他附上版本號**，
才知道對方看的是哪一版——尤其在有人把舊檔存到桌面的情況下。
改版時記得同步更新 `template.html` 裡的 `UI_VERSION` 與 `變更紀錄.md`。

| 檔案 | 內容 |
|---|---|
| `regs.db` | SQLite：`regulations` / `articles` / `revisions` / `article_refs` + FTS5 全文索引 |

## 歷史版本與「適用日期查詢」

政府補助計畫要引用「該年度適用」的條文——113 年度獎補助款要看的是
113/1/1–113/12/31 有效的版本，不是今天的版本。所以資料庫**不再覆蓋舊版**：

- `versions` / `version_articles` 兩張表會累積每一次匯入的版本，以檔案雜湊值判斷是否為新版
- 重建資料庫時，舊版本會原封不動搬回去（`load_history()`）——法規可以重新解析，歷史版本弄丟就沒了
- 每一版依通過日期自動算出適用區間；最新版的結束日為空

查詢頁左側多了「適用日期查詢」，可挑日期或直接選年度。切換後：

- 該日尚未訂定的法規不顯示
- 有那一版全文的，顯示該版條文，並註明適用區間
- **沒有那一版全文的，明白標示「未收錄該版」**，說明依沿革該日適用的是哪一次修正，
  並警告不可拿現行版本當作該年度的引用依據

最後這點是刻意的。**版本庫是從 2026 年 8 月這次匯入才開始累積的**，
在那之前的歷史版本，除非秘書室另外提供，否則本庫沒有。
以 113 年度（2024-12-31）為例，420 部中有 276 部的現行版就是當時的版本（65%），
另外 111 部在那之後修正過、需要調閱歷史版本，33 部沒有日期無法判斷。
拿現行版本充數比查不到更危險，所以程式選擇說實話。

## 與原設計文件的差異

原設計把「法規」與「版本」拆成兩張表。實作時**合併成一張**，原因是秘書室給的
資料是「一部法規一個檔、只有現行版本」，硬撐一張版本表只會得到一張每列都是
`revision_seq = 1` 的空架子。

替代做法：法規文件開頭的沿革段落被單獨切出來存進 `revisions` 表，所以
「這部法規改過幾次、哪幾年改的」查得到，只是查不到舊版條文全文。
等哪天拿到歷史版本檔案，再把 `regulations` 拆成兩張表即可，`articles` 的
外鍵改指向版本表就好，不影響已入庫的條文。

## 已知限制（都是會咬人的，請先看過）

**FTS5 trigram 查不到兩個字的詞。** 索引以三字元為單位，`MATCH '選課'` 會回傳零筆
——不是沒資料，是查不到。`search` 指令已經處理（未達三字元自動改走 `LIKE`），
但你之後自己寫查詢時務必記得。網頁端用的是 JavaScript 子字串比對，沒有這個問題。

**條號斷號通常不是解析錯誤。** 測試資料刻意做了一部缺第四條的學則，程式如實回報。
真實檔案出現斷號時，多半是原檔真的缺條（修正時整條刪除卻沒重編），
偶爾才是切條失敗。看到警示請開原檔對，不要直接改程式。

**人事室交的是連結清單，不是法規全文。** 該單位的壓縮檔裡只有一個
`法規連結網址.docx`（9 KB）。`inventory` 會把「法規檔案數 ≤1」的單位標紅提醒，
但**只有你能判斷那是單位真的只有一部法規，還是交錯東西了**。這件事要回頭找秘書室補。

**「通過會議」是猜的。** 程式取沿革中日期最新那一行上的會議名稱，抓不到才退回全文掃描。
這對格式規整的法規很準，對只有標題沒有沿革的文件會是空的。空值在網頁上顯示為「—」，
不會假裝知道。

**要點與 SOP 沒有條號。** 這類文件用「一、二、三、」或純段落，程式照原樣切，
不會硬編出「第三條」——那會製造假的權威感，讓人以為是正式條文。

**查詢頁沒有「下載次數」。** 靜態單檔網頁記不了計數。該欄位換成「條文數」，
對找法規來說也更有用。真的需要統計，要改成有後端的版本。

## 更新流程

法規每學期都在修。建議把整套流程固定成一次性動作：

1. 秘書室更新雲端資料夾
2. 下載 → 重跑 `ingest`（會重建資料庫，不是增量）
3. 看 `品質報告.csv`，處理新增的警示
4. 重跑 `build-site`，把新的 `法規查詢.html` 放回共用位置

`regulations.file_hash` 存了每個原檔的雜湊值，比對前後兩次的 `regs.db`
就知道這學期哪幾部法規動過。這件事值得做成每學期的例行檢查。
